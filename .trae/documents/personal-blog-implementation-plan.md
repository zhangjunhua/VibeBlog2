# 个人博客首版实施计划

## Context

当前工作目录为空，需要从零搭建一个用于记录学习经历、生活琐事和经验分享的个人博客。目标是先交付一个可运行的核心阅读原型，再按实际使用需求逐步迭代并上线，避免首版引入不必要的后台、数据库和客户端框架。

### 已确认需求

- 写作与发布：本地 Markdown + Git，推送后自动部署。
- 首版页面：首页、文章列表、文章详情、归档、关于。
- 视觉方向：极简文字、充足留白、清晰排版、移动端友好。
- 个人资料：昵称、头像、简介和社交链接先使用集中管理的占位信息。
- 首版不做：搜索、评论、分类、标签、CMS、登录、数据库和复杂交互。

## 技术选型

采用 **Astro 稳定版 + TypeScript + Markdown + 原生 CSS**，通过 **GitHub Actions** 自动构建并部署到 **GitHub Pages**。

- Astro 默认生成静态 HTML，核心阅读页面无需客户端 JavaScript。
- Content Collections 校验文章元数据，在本地检查和 CI 阶段发现内容错误。
- 官方 RSS、sitemap 集成及统一 SEO 元信息满足基础发布需求。
- GitHub Pages 免费、与 GitHub 工作流衔接直接，符合当前偏好；后续若访问速度或网络覆盖不理想，可在几乎不改代码的情况下迁移到 Cloudflare Pages。
- 首版不引入 React/Vue、MDX、后端或 CMS，降低维护成本。

## 实施步骤

### 1. 建立项目骨架

- 初始化 Git、npm、Astro 和严格 TypeScript 配置，提交锁文件。
- 固定受支持的 Node LTS 版本，使本地与 CI 环境一致；实施时核对 Astro 的 Node 版本要求。
- 配置 `dev`、`check`、`build`、`preview`、格式化及格式检查脚本。
- 添加 `.gitignore`，排除依赖、构建产物和缓存。

### 2. 打通最小阅读流程

先用一篇 Markdown 示例文章验证“首页 → 文章列表 → 详情 → 归档 → 关于”的完整链路，再完善视觉样式。

- 建立可复用的全站布局、文章布局和文章列表组件。
- 通过静态路由为每篇非草稿文章生成独立页面。
- 统一处理站内 URL，确保普通项目仓库的 GitHub Pages 子路径下，导航、文章、样式和资源均可用。

### 3. 建立内容模型与示例内容

文章首版字段仅包含：

- `title`：标题，必填。
- `description`：摘要及 SEO 描述，必填。
- `pubDate`：发布日期，必填。
- `updatedDate`：更新日期，可选。
- `draft`：草稿状态，默认 `false`。

实现约定：

- 草稿统一从列表、归档、RSS 和详情路由排除。
- 文章文件名使用稳定 ASCII `kebab-case`，日期采用 `YYYY-MM-DD`，显示时避免时区偏移。
- 提供学习经历、生活琐事、经验分享三篇示例文章，覆盖标题、列表、链接、代码块和引用等排版。
- 将个人资料集中到站点配置，便于后续一次替换。

### 4. 完成核心页面与站点能力

- 首页：占位个人简介、最近文章和全部文章入口。
- 文章列表：全部已发布文章，按发布日期倒序。
- 文章详情：标题、发布日期、可选更新日期和正文。
- 归档：按年份分组，年份及组内文章均倒序。
- 关于：独立于文章集合的占位个人介绍。
- 元信息：RSS、sitemap、robots.txt、canonical、description 和基础 Open Graph。

### 5. 完成响应式与可访问性

- 使用移动优先原生 CSS、系统字体、适合长文阅读的宽度和行高。
- 使用语义化结构、唯一主标题、跳转正文链接和清晰的键盘焦点。
- 确保窄屏下导航、代码块、列表和长链接不溢出，文本对比度充足。
- 首版不添加非必要动画，不依赖 JavaScript 完成阅读和导航。

### 6. 配置自动部署

- 在 GitHub Actions 中使用 `npm ci` 安装依赖，执行内容/类型检查和生产构建。
- 推送默认分支时上传 `dist/` 并部署 GitHub Pages；后续拉取请求可复用检查与构建流程。
- 工作流仅授予 Pages 所需权限，并配置部署 concurrency，避免并发发布冲突。
- 实际部署前确认 GitHub 用户名、仓库名和默认分支，据此设置 `site`、`base` 和触发分支。
- 在仓库 Settings → Pages → Source 中选择 GitHub Actions；该网页设置如无法自动完成，由用户确认操作。

├─ astro.config.mjs
├─ package.json
├─ package-lock.json

## 验证与验收

### 本地验证

1. 格式检查、`astro check` 和生产构建全部通过。
2. 使用生产预览检查五个核心页面，导航、浏览器后退和详情页直接刷新正常。
3. 验证文章排序、年份归档及草稿完全不可访问；RSS 不包含草稿。
4. 检查页面标题、description、canonical、RSS 绝对链接和 sitemap。
5. 在窄屏与宽屏下检查正文、导航、代码块和长链接，无横向滚动或资源 404。
6. 使用键盘完成导航，确认焦点可见、缩放后仍可读，浏览器控制台无异常。
7. 按项目子路径模拟 GitHub Pages，直接访问深层文章 URL，验证 CSS、图片和内部链接均包含正确前缀。

### 上线验证

1. 推送默认分支后，Actions 的检查、构建和部署全部成功。
2. 在真实 Pages 地址直接访问首页、文章详情、归档、关于、RSS、sitemap 和静态资源。
3. 修改一篇示例文章并再次推送，确认更新能自动发布；构建失败时不覆盖现有可用站点。
4. 上线前替换或明确保留示例文章及占位资料，避免误公开非真实信息。

## 后续迭代顺序

首版验收后再依据实际使用情况逐项迭代，不在当前实现中预建复杂扩展机制：

1. 替换真实个人资料，微调阅读排版。
2. 文章增多后增加标签，确有跨主题导航需求时再增加分类。
3. 内容规模足够大后增加构建期静态搜索。
4. 有读者交流需求后接入 GitHub Discussions 评论。
5. 按需增加 MDX、自动 OG 图片、自定义域名等增强功能，每项独立验收。
