第一次把静态博客部署到项目子路径时，本地预览完全正常，线上却只剩下没有样式的 HTML，文章链接也全部失效。问题并不神秘：我把开发环境的根路径当成了理所当然。

## 先复现，再修改

一开始我急着改配置，结果同时动了几个地方，反而无法判断哪一步真正有效。后来我退回原状，用和线上一致的子路径重新构建，问题立刻稳定复现。

这次以后，我把排查顺序固定下来：

- 确认线上地址是否包含仓库名前缀；
- 检查 HTML 中样式、脚本与站内链接的实际路径；
- 直接打开一篇深层文章，而不只看首页；
- 每次只修改一个变量并重新验证。

## 把路径处理放在一个地方

最可靠的修复不是逐页补上仓库名称，而是让所有内部链接经过同一个路径函数：

```ts
const base = import.meta.env.BASE_URL;
const postUrl = `${base}blog/example/`;
```

这样，本地根路径和线上子路径都由构建配置决定，页面不需要知道最终部署在哪里。

## 让错误停在发布之前

真正让我安心的不是“这次终于好了”，而是以后同类错误可以更早暴露。因此，部署流程还应该包含构建前检查，以及部署后的深层页面访问验证。

> 一次故障最有价值的产物，不只是修复本身，而是让相同故障更难再次发生。

我把这套检查留了下来。它很短，却比依赖记忆和运气可靠得多。
